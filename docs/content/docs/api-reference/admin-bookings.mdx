Admin-side booking management. Every endpoint here calls `requireRole(...)`,
which first resolves the Better Auth session (`UNAUTHENTICATED` 401 when there
is none) and then checks the caller's role against the hierarchy
`customer < staff < receptionist < manager < owner < developer`
(`FORBIDDEN` 403 when the level is too low).

<Info>
  **Base URL:** `admin.theroyalglow.in` · **Auth:** Better Auth session;
  **minimum role `receptionist`** on every endpoint on this page. These paths
  carry **no `/admin` prefix** — the admin subdomain is the namespace, so the
  full URL is e.g. `admin.theroyalglow.in/api/bookings`. The customer app
  exposes its own, distinct `/api/bookings` on `theroyalglow.in` (see
  [Bookings](/content/docs/api-reference/bookings)). Money is an integer in **paise**;
  `bookingDate` filters use `YYYY-MM-DD`; stored times render as `HH:mm:ss`.
  Timestamps are ISO-8601 UTC.
</Info>

## GET /api/bookings

Lists all bookings across customers (admin view), newest first
(`bookingDate` then `createdAt` descending). Each booking is returned with the
customer's name and email and its `booking_service` snapshot rows (ordered by
`displayOrder`). Optional query filters narrow the result set; this endpoint
returns the full filtered list and does **not** paginate (no `meta`).

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
GET /api/bookings?status=pending&serviceType=salon&date=2026-06-15
```

### Query parameters

All optional. Filters are applied with exact equality; omitting a parameter
skips that filter.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `status` | `string` | No | Booking status, e.g. pending, confirmed, in_progress, completed, cancelled, no_show, rejected. |
| `serviceType` | `string` | No | salon or spa. |
| `date` | `string` | No | YYYY-MM-DD. Matches the bookingDate exactly. |

## PATCH /api/bookings/[id]

A single endpoint that performs one of three actions, selected by the `action`
discriminator. The body is validated by `adminBookingActionSchema`
(`@rgss/types`), a discriminated union over `action`:

- **`approve`** — only valid on a `pending` booking. Assigns `staffId` to every
  service on the booking, then transitions `pending → confirmed` and stamps
  `confirmedAt`.
- **`reject`** — only valid on a `pending` booking. Transitions
  `pending → rejected`, storing `rejectionReason` and `rejectedAt`.
- **`assign`** — (re)assigns `staffId` to every service on the booking,
  regardless of status.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
PATCH /api/bookings/bk_8f2a1c9e4d
Content-Type: application/json
```

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Path. The booking id. |

### Request body

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `action` | `enum` | Yes | approve, reject, or assign. Determines which other fields are required. |
| `staffId` | `string` | No | Required for approve and assign. Non-empty staff_profile id assigned to all services. |
| `rejectionReason` | `string` | No | Required for reject. 1–500 characters. Customer-facing reason. |

## POST /api/bookings/[id]/complete

Completes a booking at the counter: collects the in-person payment method,
transitions the booking to `completed`, generates a GST-inclusive service
invoice, awards loyalty gems, and (optionally) applies an offer. Only
`confirmed` or `in_progress` bookings can be completed.

A SPA membership session is paid for with the membership's minutes. It
completes from `in_progress` only (start it first with
`POST /api/bookings/[id]/start`), takes no payment method, offer or gems, and
completing it uses the minutes it held and issues the ₹0 `membership_session`
invoice from the branch that performed it. When another branch sold the
membership, the settlement entry is recorded in the same transaction. The
response carries `remainingMinutes`, the membership's free minutes after it.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
POST /api/bookings/bk_8f2a1c9e4d/complete
Content-Type: application/json
```

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Path. The booking id. |

### Request body

`paymentMethod` is validated by `completeBookingSchema` (`@rgss/types`). The
offer/gems fields are read defensively from the raw body alongside the parsed
payload.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the page was rendered for. |
| `paymentMethod` | `enum` | Yes, except for a membership session | cash, upi, or card. Ignored for a membership session. |
| `offerId` | `string` | No | Apply a salon-only offer to the total. Validated as active and within its date range; cannot be combined with gems; one offer per customer per day. |
| `gemsRedeemedServiceId` | `string` | No | Presence signals a gems redemption on this booking. Mutually exclusive with offerId. |
| `redeemGems` | `boolean` | No | Truthy value also signals a gems redemption (mutually exclusive with offerId). |

```json
{
  "paymentMethod": "upi",
  "offerId": "off_monsoon20"
}
```

### Response

Returns the completed booking plus an invoice summary, gems earned, and any
discount applied (all amounts in paise).

```json
{

  "data": {

      "status": "completed",
      "serviceType": "salon",
      "bookingDate": "2026-06-15",
      "startTime": "11:00:00",
      "endTime": "12:00:00",
      "totalAmountPaise": 130000,
      "totalDurationMinutes": 60,
      "notes": null,
      "isWalkin": false,
      "isMembershipSession": false,
      "offerId": null,
      "spaMembershipId": null,
      "confirmedAt": "2026-06-01T07:00:00.000Z",
      "completedAt": "2026-06-15T06:30:00.000Z",
      "cancellationReason": null,
      "cancelledAt": null,
      "rejectionReason": null,
      "rejectedAt": null,
      "rescheduleCount": 0,
      "createdAt": "2026-06-01T06:15:00.000Z",
```

<Accordion title="UNAUTHENTICATED — 401">

## POST /api/bookings/[id]/start

Starts a `confirmed` booking now: the customer is in the chair. The booking
moves to `in_progress` and `startedAt` is set from the database's clock, with a
status-log entry, once; a double submit answers 409. Someone must be assigned
to every service. A booking for a later day starts on that day; move it to
today to start it sooner. A SPA membership session keeps the minutes it holds, and the
database rechecks its membership's validity at this instant, so a session
delayed past the membership's expiry can't start on its earlier booking.

**Minimum role:** `receptionist` at the active branch (`requireBranchRole('receptionist')`)

```http
POST /api/bookings/bk_8f2a1c9e4d/start
Content-Type: application/json
```

### Request body

Validated by `bookingStartSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the page was rendered for. |

### Response

Returns the started booking, with `status: "in_progress"` and `startedAt`.

### Errors

<AccordionGroup>
<Accordion title="NOT_FOUND — 404">

No booking with that id at the active branch.

</Accordion>
<Accordion title="BOOKING_INVALID_STATUS_TRANSITION — 409">

The booking isn't `confirmed`, or it was started or changed meanwhile. A
booking for a later day (its `bookingDate` is after today, IST) can't start
yet: "This booking is for DD/MM/YYYY. Start it on that day, or move it to
today first." A booking from an earlier day still starts.

</Accordion>
<Accordion title="CONFLICT — 409">

Nobody is assigned to the booking, or its services name different people. One
person does the whole booking: assign them, then start it.

</Accordion>
<Accordion title="STAFF_BUSY — 409">

The person assigned is still with another customer: a SPA booking of theirs is
running, or a salon booking is running and this one is a SPA. The message names
them. Complete that booking first, or assign someone else to this one. The
database refuses the start even when the page is stale.

</Accordion>
<Accordion title="MEMBERSHIP_EXPIRED — 409">

A membership session's membership has expired (the message names the date) or
was cancelled.

</Accordion>
<Accordion title="MEMBERSHIP_NOT_STARTED — 409">

A membership session's membership starts later; the message names its start
date.

</Accordion>
</AccordionGroup>

## POST /api/bookings/[id]/reschedule

The salon moves a `pending` or `confirmed` booking at the active branch to
another date and start time, for example off a day the branch has closed. The
booking keeps its services and length. The move records the branch settings
revision that allowed it and doesn't count against the customer's reschedule
limit.

The time is checked as the counter books: the branch must be open that day,
and the booking must fall within its hours, start on the hour or half hour, and
still be to come. The customer's booking window and lead time don't apply.

The person assigned stays when they can take the new time. Otherwise the move
goes ahead without them, in the same transaction, and the booking waits on the
dashboard for someone else: they are on approved leave that day, their weekly
schedule doesn't cover the time, or they have another booking then.
`needsStaff` says so.

**Minimum role:** `receptionist` at the active branch (`requireBranchRole('receptionist')`)

```http
POST /api/bookings/bk_8f2a1c9e4d/reschedule
Content-Type: application/json
```

### Request body

Validated by `adminBookingMoveSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the page was rendered for. |
| `bookingDate` | `string` | Yes | The new IST date, `YYYY-MM-DD`. |
| `startTime` | `string` | Yes | The new IST start time, `HH:mm`. |

```json
{
  "branchId": "br_rayasandra01",
  "bookingDate": "2026-06-16",
  "startTime": "11:30"
}
```

### Response

The moved booking, and whether it now needs someone else.

```json
{
  "success": true,
  "data": {
    "booking": {
      "id": "bk_8f2a1c9e4d",
      "status": "confirmed",
      "bookingDate": "2026-06-16",
      "startTime": "11:30:00",
      "endTime": "12:30:00",
      "rescheduleCount": 0
    },
    "needsStaff": false
  }
}
```

### Errors

<AccordionGroup>
<Accordion title="VALIDATION_ERROR — 400">

Body fails `adminBookingMoveSchema` (missing or malformed date or time).

</Accordion>
<Accordion title="NOT_FOUND — 404">

No booking with that id at the active branch.

</Accordion>
<Accordion title="BRANCH_CONTEXT_CHANGED — 409">

The page was rendered for another branch than the active one.

</Accordion>
<Accordion title="BOOKING_INVALID_STATUS_TRANSITION — 409">

The booking isn't `pending` or `confirmed` (one under way can't be moved), or
it changed meanwhile.

</Accordion>
<Accordion title="BOOKING_SLOT_UNAVAILABLE — 409">

The branch is closed that day (the message names the closure and how to remove
it), the time is outside the branch's hours, off the half-hour grid or already
passed, or someone took the person for that time meanwhile.

</Accordion>
<Accordion title="MEMBERSHIP_EXPIRED — 409">

A membership session can't move outside its membership's validity; it keeps its
slot.

</Accordion>
</AccordionGroup>

## POST /api/bookings/[id]/cancel

The salon cancels a `pending` or `confirmed` booking at the active branch,
saying why: a day the branch closed, nobody free to do it, or the customer's
call. The cancellation is never counted as the customer's late cancellation.
Gems the booking was made with go back to the customer, and a membership
session's held minutes return to its membership, in the same write. The
customer sees the booking cancelled with the reason.

**Minimum role:** `receptionist` at the active branch (`requireBranchRole('receptionist')`)

```http
POST /api/bookings/bk_8f2a1c9e4d/cancel
Content-Type: application/json
```

### Request body

Validated by `adminBookingCancelSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the page was rendered for. |
| `reason` | `string` | Yes | 1–500 characters, shown to the customer. |

```json
{
  "branchId": "br_rayasandra01",
  "reason": "The salon is closed for Diwali on 15/06/2026."
}
```

### Response

The cancelled booking, with `status: "cancelled"`, `cancellationReason` and
`cancelledAt`.

### Errors

<AccordionGroup>
<Accordion title="VALIDATION_ERROR — 400">

No reason, a blank one, or one over 500 characters.

</Accordion>
<Accordion title="NOT_FOUND — 404">

No booking with that id at the active branch.

</Accordion>
<Accordion title="BRANCH_CONTEXT_CHANGED — 409">

The page was rendered for another branch than the active one.

</Accordion>
<Accordion title="BOOKING_INVALID_STATUS_TRANSITION — 409">

The booking isn't `pending` or `confirmed` (complete one under way instead), or
it changed meanwhile.

</Accordion>
</AccordionGroup>

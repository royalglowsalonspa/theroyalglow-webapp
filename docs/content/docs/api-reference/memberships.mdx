description: Customer SPA membership view plus the admin endpoints to create, list, inspect, cancel, and record sessions against memberships.

---

SPA memberships are hour-based: a customer buys a tier (e.g. Silver 8hrs, Gold
15hrs) valid for a fixed number of days, and each SPA session deducts its
duration from the remaining hours. There is one customer-facing read endpoint
(`theroyalglow.in/api/membership`, singular); everything else is an admin
endpoint served from `admin.theroyalglow.in` (e.g.
`admin.theroyalglow.in/api/memberships`, plural) and is role-gated.

<Info>
  **Base URLs:** the customer read endpoint is `https://theroyalglow.in`; the
  admin endpoints are served from `https://admin.theroyalglow.in` with **no
  `/api/admin/` segment** — the subdomain is the namespace (e.g.
  `admin.theroyalglow.in/api/memberships`, `.../api/membership-tiers`). Roles
  are hierarchical: `customer` < `staff` <
  `receptionist` < `manager` < `owner` < `developer`. Money is an integer in
  **paise** (₹10,000 = `1000000`). **Hours are stored as minutes** — the
  `*HoursMinutes` fields hold minutes, so Silver 8hrs = `480` and Gold 15hrs =
  `900`. Dates in request bodies are `YYYY-MM-DD`; timestamps in responses are
  UTC ISO strings. Membership status is one of `active`, `expired`, `cancelled`.
  Membership numbers use the format `RG-MEM-{YY}-{branchNumber}-{5 random}`.
</Info>

## GET `theroyalglow.in/api/membership`

Returns the signed-in customer's own membership data: the single `active`
membership (if any), an array of `past` (expired/cancelled) memberships, and the
`sessions` history for the active membership. Strictly scoped to the
authenticated customer — it never exposes another customer's data. When there is
no active membership, `active` is `null` and `sessions` is an empty array.

**Minimum role:** `customer` (`requireSession`)

```http
GET /api/membership
```

## POST `admin.theroyalglow.in/api/memberships`

Creates a SPA membership and its `membership_purchase` invoice atomically. The
handler enforces one active membership per customer (a friendly 409 ahead of the
DB partial-unique index), resolves the tier for its name snapshot, computes the
expiry from `startDate` + `validityDays`, and splits the GST-inclusive price into
base + GST on the invoice. No gems are earned on purchase. A best-effort expiry
notice job is scheduled but never affects the response.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
POST /api/memberships
Content-Type: application/json
```

### Request body

Validated by `createMembershipSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `customerId` | `string` | Yes | Non-empty user id of the customer. |
| `tierId` | `string` | Yes | Non-empty tier id; must resolve to an active tier. |
| `hoursMinutes` | `integer` | Yes | Positive. Total membership hours in minutes (Silver 480, Gold 900). |
| `pricePaise` | `integer` | Yes | Non-negative. GST-inclusive price in paise. |
| `startDate` | `string` | Yes | YYYY-MM-DD. |
| `validityDays` | `integer` | Yes | Positive. Days from startDate until expiry. |
| `paymentMethod` | `enum` | Yes | cash, upi, or card. |
| `notes` | `string` | No | Max 500 characters. |

```json
{
  "customerId": "usr_abc123",
  "tierId": "tier_gold",
  "hoursMinutes": 900,
  "pricePaise": 1500000,
  "startDate": "2026-06-01",
  "validityDays": 90,
  "paymentMethod": "upi",
  "notes": "Anniversary gift package."
}
```

## POST `admin.theroyalglow.in/api/memberships/[id]/sessions`

"Record now": starts a SPA session against a membership at the active branch.
The session is an in-progress ₹0 booking flagged as a membership session
(booking number suffixed `-M`), started now on today's IST date, with its
`booking_service` rows. The database holds the session's minutes from the
membership in the same transaction, so the membership's free minutes are its
total less used less held. Completing the session from its booking
(`POST /api/bookings/[id]/complete`, no payment method) uses the minutes and
issues the ₹0 `membership_session` invoice. No gems are earned.

One person does the whole session, and it starts now, so the request names
them. The handler checks the membership's state and free minutes up front,
validates the services and that the person works at the active branch, and
snapshots their name. The database checks again when it holds the minutes: if
the membership stopped being active, expired, or no longer has the minutes free
(for example, another branch started a session at the same moment), or the
person has another booking now or is still with another customer, nothing is
written and the request fails with a 409.

Send an `idempotencyKey` to make retries safe. A request whose key already
started a session on this membership returns `200 OK` with that session and
`duplicate: true`, without holding again. This holds even when the first
attempt held the last of the hours.

**Booking a session ahead.** Send a `startTime` with the `bookingDate` to book
the session for that day and time instead: a `confirmed` booking that holds
its minutes from now until it is started and completed from its booking, or
cancelled. The time is checked as the counter books: the active branch must be
open that day, and the session must fall within its hours, start on the hour
or half hour, and still be to come. The membership must be valid at the
planned start, and the person must be free and scheduled then. A booking for a
later day can't be started before that day.

**Minimum role:** `receptionist` at the active branch (`requireBranchRole('receptionist')`)

```http
POST /api/memberships/mem_9aZ2bYc31/sessions
Content-Type: application/json
```

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Path. The membership id. |

### Request body

Validated by `recordSessionSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the form was rendered for. A different active branch answers 409 `BRANCH_CONTEXT_CHANGED`. |
| `staffId` | `string` | No | The one person doing the whole session; must work at the active branch and be free at its time: now, or the time a session booked ahead is for. Required unless every line names the same person. |
| `services` | `array` | Yes | At least one service line (see fields below). |
| `services[].serviceId` | `string` | Yes | Non-empty; must be an existing service. |
| `services[].staffId` | `string` | No | For forms that name the person per line: every line must name the same person, and the same one as `staffId` when both are sent. |
| `services[].durationMinutes` | `integer` | Yes | Positive. Minutes to hold for this line. |
| `bookingDate` | `string` | No | YYYY-MM-DD. Without `startTime` it must be today (IST): a session recorded now takes today's date. Required with `startTime`. |
| `startTime` | `string` | No | HH:mm (IST). Books the session ahead for `bookingDate` at this time. |
| `idempotencyKey` | `string` | No | 8–64 characters from `A-Z a-z 0-9 _ -`, e.g. `crypto.randomUUID()`. Use a new key for each session attempt; reuse it only to retry the same request. |

```json
{
  "branchId": "branch_rayasandra",
  "staffId": "stf_therapist01",
  "services": [
    {
      "serviceId": "svc_aromamassage",
      "durationMinutes": 120
    }
  ],
  "idempotencyKey": "3f2504e0-4f89-11d3-9a0c-0305e82c3301"
}
```

### Response

Returns `201 Created` with the in-progress booking (or, for a session booked
ahead, the `confirmed` booking with `startedAt: null`), `invoice: null` (the
invoice is issued on completion), the membership's free minutes after the

with the original session, its invoice once the session has completed, and
`duplicate: true`.

```json
{
  "success": true,
  "data": {
    "booking": {
      "id": "bk_77aa11bb22",
      "bookingNumber": "BK-RS-2606-S-44120-M",
      "branchId": "branch_rayasandra",
      "customerId": "usr_abc123",
      "status": "in_progress",
      "serviceType": "spa",
      "bookingDate": "2026-06-10",
      "startTime": "15:30:00",
      "endTime": "17:30:00",
      "totalAmountPaise": 0,
      "totalDurationMinutes": 120,
      "isMembershipSession": true,
      "spaMembershipId": "mem_9aZ2bYc31",
      "startedAt": "2026-06-10T10:00:00.000Z",
      "completedAt": null
```

<AccordionGroup>

</Accordion>
<Accordion title="STAFF_BUSY — 409">

<Accordion title="NOT_FOUND — 404">

</Accordion>
<Accordion title="MEMBERSHIP_NOT_STARTED — 409">

</Accordion>
<Accordion title="INTERNAL_ERROR — 500">

Unexpected/transient failure. `retryable: true`.

</Accordion>

## POST `admin.theroyalglow.in/api/memberships/[id]/cancel`

Cancels a membership sold at the active branch. In one transaction it cancels
the membership's sessions booked but not started, which gives their minutes
back, each with a status-log entry naming the person cancelling; then it sets
the membership to `cancelled` and appends the reason to its notes. While a
session is in progress the request is refused with a 409: complete the session
first. Unused hours are forfeited; refunds are handled offline.

**Minimum role:** the selling branch's Manager or Owner, or the Developer,
working at the selling branch (`requireBranchRole` plus the selling-branch
check)

```http
POST /api/memberships/mem_9aZ2bYc31/cancel
Content-Type: application/json
```

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Path. The membership id. |

### Request body

Validated by `cancelMembershipSchema` (`@rgss/types`).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `branchId` | `string` | Yes | The branch the page was rendered for. A different active branch answers 409 `BRANCH_CONTEXT_CHANGED`. |
| `reason` | `string` | Yes | Trimmed, 1–500 characters. Appended to the membership notes as "Cancelled: {reason}". |

```json
{
  "branchId": "branch_rayasandra",
  "reason": "Customer relocated out of the city."
}
```

### Response

Returns the membership's id and new status, and how many sessions booked but
not started were cancelled with it.

```json
{
  "success": true,
  "data": {
    "id": "mem_9aZ2bYc31",
    "status": "cancelled",
    "cancelledSessions": 1
  }
}
```

</Accordion>

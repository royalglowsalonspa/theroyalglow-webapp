# Leads

The lead surface has two halves. `POST /api/leads` is the **only**
unauthenticated write endpoint in this phase — it backs the `/book` Meta-ad
landing page. Everything under `/api/admin/leads` is the receptionist-facing
pipeline and requires a Better Auth session with at least the `receptionist`
role.

<Callout type="info">
  Roles are hierarchical: `customer` < `staff` < `receptionist` < `manager` <
  `owner` < `developer`. A handler that calls `requireRole('receptionist')`
  also admits `manager`, `owner`, and `developer`. Phone numbers are normalised
  to canonical `+91XXXXXXXXXX` in the business layer before storage. Lead
  pipeline: `new → contacted → follow_up → booked → won/lost`.
</Callout>

## POST /api/leads

Public lead capture from the Meta-ad landing page. The endpoint is per-IP
rate-limited and strictly Zod-validated. It deliberately echoes back nothing
beyond the created `leadId` (no PII). The `source` defaults to `meta_ad` when
omitted.

**Minimum role:** Public — no session required (rate-limited per IP: 5 requests
per 60s window).

```http
POST /api/leads
Content-Type: application/json
```

### Request body

Validated by `createLeadSchema` (`@rgss/types`).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `name` | string | Required | Trimmed, 1–120 characters. |
| `phone` | string | Required | Indian 10-digit mobile, optionally `+91`/`0`-prefixed (`/^(?:\+?91\|0)?[6-9]\d{9}$/`). Normalised to `+91XXXXXXXXXX`. |
| `email` | string | Optional | Must be a valid email if present. |
| `serviceInterestedId` | string | Optional | Non-empty service id the lead is interested in. |
| `source` | string | Optional | Max 40 chars. Defaults to `meta_ad` in the handler. |
| `utmSource` | string | Optional | Max 120 chars. |
| `utmMedium` | string | Optional | Max 120 chars. |
| `utmCampaign` | string | Optional | Max 120 chars. |
| `utmContent` | string | Optional | Max 120 chars. |
| `utmTerm` | string | Optional | Max 120 chars. |

```json
{
  "name": "Priya Sharma",
  "phone": "9876543210",
  "email": "priya@example.com",
  "serviceInterestedId": "svc_facialglow01",
  "utmSource": "facebook",
  "utmMedium": "paid_social",
  "utmCampaign": "monsoon_glow_2026",
  "utmContent": "carousel_v2",
  "utmTerm": "facial"
}
```

### Response

Returns `201 Created` with only the new lead id.

```json
{
  "success": true,
  "data": {
    "leadId": "ld_7Qx2aMce91"
  }
}
```

### Errors

| Code | Status | When |
| --- | --- | --- |
| `RATE_LIMITED` | 429 | More than 5 requests from the same IP within the 60s window. `retryable: true`. |
| `VALIDATION_ERROR` | 400 | Body fails `createLeadSchema`. `details` carries the per-field errors. |
| `INTERNAL_ERROR` | 500 | Unexpected/transient failure. `retryable: true`. |

## GET /api/admin/leads

Returns the lead pipeline, newest first. Each row is a flat lead enriched with
the service-interest name plus two computed fields: `daysSinceCapture` (whole
days since `createdAt`) and `isStale` (whether the lead has gone too long
without movement for its status). Pass `?status=` to bucket a single column of
the kanban board.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
GET /api/admin/leads?status=new
```

| Parameter | In | Type | Required | Notes |
| --- | --- | --- | --- | --- |
| `status` | query | string | Optional | One of `new`, `contacted`, `follow_up`, `booked`, `won`, `lost`. Omit for all leads. |

### Response

```json
{
  "success": true,
  "data": {
    "leads": [
      {
        "id": "ld_7Qx2aMce91",
        "name": "Priya Sharma",
        "phone": "+919876543210",
        "email": "priya@example.com",
        "serviceInterestedId": "svc_facialglow01",
        "status": "new",
        "source": "meta_ad",
        "utmCampaign": "monsoon_glow_2026",
        "utmMedium": "paid_social",
        "utmSource": "facebook",
        "utmContent": "carousel_v2",
        "utmTerm": "facial",
        "assignedTo": null,
        "convertedBookingId": null,
        "lastContactedAt": null,
        "createdAt": "2026-06-01T05:30:00.000Z",
        "updatedAt": "2026-06-01T05:30:00.000Z",
        "serviceName": "Glow Facial",
        "daysSinceCapture": 0,
        "isStale": false
      }
    ]
  }
}
```

### Errors

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | No active session. |
| `FORBIDDEN` | 403 | Session role is below `receptionist`. |
| `INTERNAL_ERROR` | 500 | Unexpected/transient failure. `retryable: true`. |

## POST /api/admin/leads

Creates a lead manually from inside the admin portal (e.g. a phone enquiry).
Identical body to the public endpoint, but `source` is fixed to `manual` by
`manualLeadSchema` and the handler — it always overrides `source` to `manual`.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
POST /api/admin/leads
Content-Type: application/json
```

### Request body

Validated by `manualLeadSchema` (`@rgss/types`) — extends `createLeadSchema`
with `source: 'manual'` (literal, defaults to `manual`).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `name` | string | Required | Trimmed, 1–120 characters. |
| `phone` | string | Required | Indian 10-digit mobile. Normalised to `+91XXXXXXXXXX`. |
| `email` | string | Optional | Valid email if present. |
| `serviceInterestedId` | string | Optional | Non-empty service id. |
| `source` | `"manual"` | Optional | Literal; defaults to `manual` and is forced to `manual` by the handler. |
| `utmSource` / `utmMedium` / `utmCampaign` / `utmContent` / `utmTerm` | string | Optional | Max 120 chars each. |

```json
{
  "name": "Walk-in Enquiry",
  "phone": "+919812345678",
  "serviceInterestedId": "svc_haircut001"
}
```

### Response

Returns `201 Created` with the new lead id.

```json
{
  "success": true,
  "data": {
    "leadId": "ld_3Kp9bWfa20"
  }
}
```

### Errors

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | No active session. |
| `FORBIDDEN` | 403 | Session role is below `receptionist`. |
| `VALIDATION_ERROR` | 400 | Body fails `manualLeadSchema`. `details` carries per-field errors. |
| `INTERNAL_ERROR` | 500 | Unexpected/transient failure. `retryable: true`. |

## PATCH /api/admin/leads/[id]

Updates a lead's status, enforcing the pipeline state machine. When the new
status is `contacted`, the handler also stamps `lastContactedAt`. Marking a lead
`lost` requires a non-empty `reason`.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

The allowed transitions (`assertLeadTransition`) are:

| From | Allowed to |
| --- | --- |
| `new` | `contacted`, `booked`, `lost` |
| `contacted` | `follow_up`, `booked`, `lost` |
| `follow_up` | `booked`, `lost` |
| `booked` | `won`, `lost` |
| `won` | _(terminal — no moves)_ |
| `lost` | _(terminal — no moves)_ |

Same-status moves are not in the map and are therefore rejected.

```http
PATCH /api/admin/leads/ld_7Qx2aMce91
Content-Type: application/json
```

| Parameter | In | Type | Required | Notes |
| --- | --- | --- | --- | --- |
| `id` | path | string | Required | The lead id. |

### Request body

Validated by `updateLeadStatusSchema` (`@rgss/types`).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `status` | enum | Required | One of `new`, `contacted`, `follow_up`, `booked`, `won`, `lost`. |
| `reason` | string | Conditional | Max 500 chars. **Required** (non-empty) when `status` is `lost`. |

```json
{
  "status": "lost",
  "reason": "Chose a competitor closer to home."
}
```

### Response

Returns the updated lead row.

```json
{
  "success": true,
  "data": {
    "lead": {
      "id": "ld_7Qx2aMce91",
      "name": "Priya Sharma",
      "phone": "+919876543210",
      "email": "priya@example.com",
      "serviceInterestedId": "svc_facialglow01",
      "status": "lost",
      "source": "meta_ad",
      "utmCampaign": "monsoon_glow_2026",
      "utmMedium": "paid_social",
      "utmSource": "facebook",
      "utmContent": "carousel_v2",
      "utmTerm": "facial",
      "assignedTo": "usr_reception01",
      "convertedBookingId": null,
      "lastContactedAt": "2026-06-01T09:10:00.000Z",
      "createdAt": "2026-06-01T05:30:00.000Z",
      "updatedAt": "2026-06-02T11:00:00.000Z"
    }
  }
}
```

### Errors

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | No active session. |
| `FORBIDDEN` | 403 | Session role is below `receptionist`. |
| `VALIDATION_ERROR` | 400 | Body fails `updateLeadStatusSchema`, or `status` is `lost` without a non-empty `reason`. |
| `NOT_FOUND` | 404 | No lead with that id. |
| `BUSINESS_RULE_VIOLATION` | 409 | Illegal status transition (move not allowed by the state machine, including same-status moves). |
| `INTERNAL_ERROR` | 500 | Unexpected/transient failure. `retryable: true`. |

## POST /api/admin/leads/[id]/notes

Appends a note to a lead. The note's author is taken from the session, not the
request body.

**Minimum role:** `receptionist` (`requireRole('receptionist')`)

```http
POST /api/admin/leads/ld_7Qx2aMce91/notes
Content-Type: application/json
```

| Parameter | In | Type | Required | Notes |
| --- | --- | --- | --- | --- |
| `id` | path | string | Required | The lead id. |

### Request body

Validated by `addLeadNoteSchema` (`@rgss/types`).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `content` | string | Required | Trimmed, 1–1000 characters. |

```json
{
  "content": "Left a voicemail, will retry tomorrow morning."
}
```

### Response

Returns `201 Created` with the new note.

```json
{
  "success": true,
  "data": {
    "note": {
      "id": "ldn_5gH6iJ7kL8",
      "leadId": "ld_7Qx2aMce91",
      "authorId": "usr_reception01",
      "content": "Left a voicemail, will retry tomorrow morning.",
      "createdAt": "2026-06-02T04:00:00.000Z"
    }
  }
}
```

### Errors

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | No active session. |
| `FORBIDDEN` | 403 | Session role is below `receptionist`. |
| `VALIDATION_ERROR` | 400 | Body fails `addLeadNoteSchema` (empty or over-long content). |
| `INTERNAL_ERROR` | 500 | Unexpected/transient failure. `retryable: true`. |

<Callout type="warn">
  Unlike `GET`/`PATCH` on `/api/admin/leads/[id]`, this handler does **not**
  pre-check that the lead exists. Posting a note for a non-existent `id` fails on
  the foreign-key constraint and surfaces as `INTERNAL_ERROR` (500) rather than
  `NOT_FOUND`.
</Callout>
